# Секреты

`secrets` — одна зашифрованная строка с YAML-словарём внутри. Composer использует
age, расшифровывает блок перед объединением `base.yaml` и `stage.yaml` и передаёт
значения шаблонам через `.Secrets`. Настройки `app` и `compose` остаются открытыми.

## Один ключ для всех приложений

Создайте ключ вне GitOps-репозитория:

```sh
mkdir -p "$HOME/.config/composer"
chmod 700 "$HOME/.config/composer"
age-keygen -o "$HOME/.config/composer/age.txt"
chmod 600 "$HOME/.config/composer/age.txt"
```

Перенесите этот ключ на сервер с правами `0600` для пользователя Composer.
Укажите его один раз в host YAML; относительный путь считается от этого файла:

```yaml
age_key_file: /etc/composer/age.txt
```

Поддерживается один native X25519 age identity в файле. Для открытых vars ключ
не нужен. `.sops.yaml`, `recipient` и другие настройки в приложениях не нужны.

## Добавление и изменение

Подайте YAML-словарь на stdin. Команда напечатает только зашифрованное значение:

```sh
composer secrets encrypt --key-file "$HOME/.config/composer/age.txt" <<'YAML'
database:
  password: demo-password
YAML
```

Это демонстрационный пароль. Реальные значения передавайте из защищённого файла
или через stdin, учитывая историю и запись терминала. Скопируйте результат
в конец `vars/base.yaml` нужного приложения:

```yaml
app:
  database:
    host: db

compose:
  services:
    api:
      image: your-app:version

secrets: age:... # полная строка из команды
```

В шаблоне можно обратиться к `.Secrets.database.password` или объединить
весь словарь с настройками приложения:

```gotemplate
{{ merge .Vars.app .Secrets | toYAML }}
```

Для чтения подайте только значение `age:…`, без ключа `secrets:`:

```sh
composer secrets decrypt --key-file "$HOME/.config/composer/age.txt"
# Вставьте строку age:… и завершите ввод Ctrl-D.
```

Для изменения расшифруйте блок, измените YAML и зашифруйте заново. В Git
попадает только новая строка. `stage.yaml` шифруется так же и может содержать
только переопределяемые секреты; словари объединяются рекурсивно.

## Применение

После commit работают обычные `validate`, `plan`, `apply` и `run`. Изменение
используемого секрета пересоздаёт контейнеры соответствующего проекта с прежним
образом. Повторное шифрование тех же значений не вызывает выкатку. `$`, `$$`
и `${…}` сохраняются буквально. Ошибка ключа или повреждение шифротекста
сохраняет текущий проект и возвращает ошибку без содержимого секретов.

Готовые конфиги записываются в `state_dir`, включая при `validate` и `plan`.
Каталоги имеют права `0700`, конфиги — `0444` (`0555` для исполняемых файлов).
Монтируйте их с `:ro` и защищайте резервные копии. Старые версии сохраняются
до удаления проекта. Compose environment доступен пользователям Docker.

Прежний формат SOPS больше не читается. Для миграции расшифруйте старый файл
через SOPS, передайте его словарь `secrets` команде `composer secrets encrypt`,
замените блок результатом и удалите `sops` и `.sops.yaml`. Если были зашифрованы
поля `app`, перенесите секретные значения в `secrets` и обновите шаблоны.
